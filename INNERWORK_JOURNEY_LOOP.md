# Innerwork Journey Loop

Journey memory should influence tomorrow's **practice choice**, not turn the experience into a scorecard.

## Daily loop

```text
Catatan dominant issue
  ↓
Navigator and wellness capacity
  ↓
Practice selected
  ↓
Completion + brief response captured
  ↓
Tomorrow's Catatan sees the response
  ↓
Same issue continues, softens, or changes
  ↓
Next practice repeats, deepens, or rotates
```

## Minimum completion record

- dominant issue ID
- practice ID and mechanism
- Navigator mode
- planned and actual duration
- completed, skipped, or stopped
- optional post-practice state: lighter, same, heavier
- optional one-line observation
- date and recent repetition count

Do not require a written reflection to count a completed body or rest practice.

## Tomorrow rules

| Yesterday | Tomorrow response |
|---|---|
| Completed and felt lighter | Continue the same issue with a slightly deeper or real-life practice |
| Completed and felt the same | Change mechanism, not issue: journal → body, body → boundary action |
| Completed and felt heavier | Reduce duration/intensity; offer regulation first |
| Started but stopped | Treat as capacity information, not failure |
| Skipped once | Offer a smaller version or a different mechanism |
| Skipped repeatedly | Recheck whether Catatan's issue is accurate; do not keep prescribing the same task |
| Same practice completed recently | Rotate unless repetition is intentionally therapeutic and welcomed |
| Dominant issue resolved/softened | Let Catatan select a new issue; do not manufacture continuity |

## Progression example

```text
Day 1 — Over-responsibility / RECOVERY
Notice one burden that may not be yours — 3 min

Day 2 — issue remains / REFLECTION
Separate “mine” and “theirs” in a short journal — 8 min

Day 3 — issue remains / GROWTH
Use one gentle boundary sentence — 12 min

Day 4 — user reports relief
Maintain the boundary; do not escalate merely to create novelty
```

## New-user behavior

When no history exists:

- select from current issue + Navigator + wellness only;
- do not claim prior consistency;
- start with the lowest sufficient intensity;
- establish preference from actual responses, not profile assumptions.

## Anti-gamification rule

Streaks may inform whether consistency needs support, but they must never override current capacity or pressure the user to preserve a number.
