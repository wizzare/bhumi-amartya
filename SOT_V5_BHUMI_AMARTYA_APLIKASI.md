## 1. Global Localization Strategy

| Aspect | Decision |
|--------|----------|
| **Supported locales** | `id-ID` (default), `en-US`, `ms-MY`, `ja-JP`, `zh-CN`, `hi-IN` |
| **Fallback hierarchy** | If a string is missing for a locale, fall back to `en-US`; if still missing, fall back to `id-ID`. |
| **Translation workflow** | ‣ Source strings reside in `src/locales/en-US.json`.
‣ External translation agency provides locale‑specific JSON files.
‣ All files are version‑controlled and must pass the **Localization Lint** (no duplicate keys, proper ICU syntax). |
| **Cultural adaptation** | Date, number, and currency formatting use **Intl API** with locale‑specific options.  Calendar UI shows the week start according to locale conventions (Monday for id‑ID, Sunday for en‑US, etc.). |
| **Right‑to‑left support** | Not required for target locales (all LTR). |
| **Content moderation** | User‑generated text passes through the **Bhumi AI Moderation Service** before storage, respecting locale‑specific profanity filters. |

## 2. UI / UX Guidelines

- **Primary language**: All static UI text must be displayed in the device‑selected locale; the default language when the device has no matching locale is Indonesian (`id-ID`).
- **Language selector**: A dropdown list of locale names (e.g., *Bahasa Indonesia*, *English (US)*). **Do not use flags** as icons.
- **Typography**:
  - Use **Inter** for Latin scripts.
  - Use **Noto Sans JP** for Japanese, **Noto Sans SC** for Simplified Chinese, **Noto Sans Devanagari** for Hindi.
  - Font‑size scaling respects the OS accessibility settings.
- **Date / Time**: Display using `Intl.DateTimeFormat` with locale‑specific patterns (`dd MMM yyyy`, `HH:mm`).
- **Number / Currency**: Use `Intl.NumberFormat` with appropriate currency symbols (`IDR`, `USD`, `MYR`, `JPY`, `CNY`, `INR`).
- **Accessibility**: All localized strings must have an associated content‑description for screen readers.

## 3. AI‑Powered Features

| Feature | Description | Localization Impact |
|---------|-------------|----------------------|
| **Smart Suggestions** | Contextual prompts generated by the Bhumi AI model to guide user actions. | Must be translated per locale; placeholders (`{{userName}}`) remain unchanged across languages. |
| **Sentiment Analysis** | Detects sentiment of user‑written messages to surface appropriate UI cues. | Model runs on English‑normalized text; locale‑specific stop‑words are handled via language‑specific tokenizers. |
| **Moderation** | Filters profanity, hate speech, and misinformation. | Uses locale‑aware word lists; decision thresholds are uniform across locales. |

## 4. Architecture & Code Ownership

- **Version source of truth**: `package.json` (`version: 5.0.0`) and `android/app/build.gradle` (`versionName "5.0"`, `versionCode 100`).
- **Runtime version provider**: `lib/config/buildInfo.ts` – **must be kept in sync** with the above files during every release.
- **Localization assets**: Located under `src/locales/`.
- **Locale selector component**: `src/components/LocaleSwitcher.tsx` – implements the dropdown without flag icons.
- **AI service clients**: `src/services/aiClient.ts` – respects `Accept-Language` header derived from the current locale.

> **Canonical owners** for V5 release metadata are the `package.json`, `android/app/build.gradle`, and `lib/config/buildInfo.ts`.  Any divergence must be resolved before a signed AAB can be considered final.

## 5. Release Checklist (V5)

1. **Version synchronization** – ensure `package.json`, `build.gradle`, and `buildInfo.ts` all report versionName `5.0` and versionCode `100`.
2. **Locale files** – all supported locales present, validated, and committed.
3. **Language selector** – flag‑less UI verified on Android and iOS simulators.
4. **AI prompts** – all strings extracted to locale files and translated.
5. **Accessibility audit** – screen‑reader labels verified for each language.
6. **Signed AAB generation** – build with `./gradlew bundleRelease` and verify manifest entries (`versionName`, `versionCode`, `package`).
7. **Checksum documentation** – record SHA‑256 of the final AAB in `RELEASE_METADATA.json`.
8. **No pending work‑tree changes** – `git status` must be clean except for documentation files.
9. **No code changes** – this SoT document does not modify any source files.
